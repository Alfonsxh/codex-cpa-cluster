# 配置中心

## 范围

React 配置中心通过 Go Admin 的细粒度接口读取和修改组织设置，不再把全部系统状态装入一个大响应。当前页面入口是 `/admin/configuration`，契约以 [OpenAPI](../api/openapi.yaml) 和 `internal/admin` 为准。

## 页面分类与保存

配置中心保留六个同级分类，系统设置紧接品牌与身份：

| 分类 | 内容 |
|---|---|
| 品牌与身份 | 名称、Logo、公开地址、邮箱后缀、Key 前缀与客户端导出 |
| 系统设置 | 系统时区、Portal 登录有效期、管理密钥、初始密码与推理强度配色 |
| 请求与账号 | 上游代理、重试、会话保持、账号切换、供应端口、监听、镜像与日志 |
| 用量与额度 | 额度（用户额度、官方额度查询与用量维护）、模型倍率、推理倍率、用量采集 |
| 通知设置 | 企业微信通知（通知开关、Webhook、发送计划与额度预警） |
| 数据与审计 | 安全归档、存储状态与审计记录 |

左侧采用分类与子项两级导航，分类默认全部展开：点击分类展开或收起子项，点击子项后右侧仅展示对应配置内容，不再显示分类说明、分区标题或折叠栏。当前子项高亮，未保存数量同时显示在分类与子项上；窄屏通过“选择配置子项”展开同一导航。搜索覆盖所有配置字段和独立操作，选中结果会展开所属分类、切换子项并定位可操作控件。旧的 `?group=...&key=...` 和 `?section=access|backups|storage|audit` 链接继续有效，字段定位优先于旧分类。

配置中心沿用其他管理页面的顶部与左右内容边距，与页头及其他页面卡片对齐；底部继续延伸至页面底部。桌面分类卡片宽 280px，子项名称保持单行，修改数量独立占位。

所有可编辑配置使用同一套三列布局，顺序固定为“配置项 → 生效方式 → 配置值”：第一列名称和说明左对齐，第二列桌面固定 104px、标记居中，第三列表头、控件及输入值左对齐。模型倍率采用同样顺序；推理强度的中文、英文在第一列内并排居中，生效方式在第二列，颜色或倍率控件在第三列。生效方式表示保存后的应用行为，每行只出现一次。

模型倍率页直接展示配置表，不再显示顶部计费说明、模型摘要或重复标题。模型与推理倍率中，有效值大于 1 时强调数值并显示“高倍率”标记；标记随当前编辑值变化，1 倍及以下不显示。

名称、前缀、环境变量、域名、URL、镜像地址和密码使用完整的配置值列；数字、时间、倍率、次数与布尔值采用紧凑控件，单位放在数值框外；时区和普通选择框最大 360px，颜色组合为 144px。所有宽度都受值列约束。数字控件可随内容增长，但列宽与左边界不随输入变化；普通长文本可通过控件标题查看完整值，地址预览和错误提示可换行。秘密输入不会在控件标题中回显。

控件默认透明且无可见边框，配置值控件左边缘位于列左边界；输入框、时区和下拉选择的文字统一保留 10px 左内边距，配置值表头使用同一内边距，与框内文字起点对齐；数字控件的测宽镜像使用相同间距。悬停提供轻微底色，聚焦和错误边界通过不占布局空间的轮廓与阴影显示，避免编辑时文字位移。文本与数字输入按 Enter 结束当前字段编辑并保留草稿，按 Escape 撤销本次聚焦期间的编辑，失焦不触发保存；下拉菜单自行处理选择和取消。未保存字段同时使用行底色和文字标记，错误显示在值下方；保存中禁用编辑和重复提交，下拉菜单关闭。加载骨架使用相同的列结构，读取失败保留现有重试入口。

配置中心页面可用宽度小于 720px 时收起左侧导航；右侧卡片可用宽度小于 720px 时，普通配置将名称和说明放在第一行，下一行左侧为 88px 的生效方式，右侧为配置值。配色与倍率表保留至少 610px 的完整列宽，在卡片内横向滚动，保存栏按空间换行。

右侧配置内容与保存状态、操作按钮共用一张延伸到页面底部的卡片。内容区统一承载纵向与横向滚动，普通配置、模型倍率、推理倍率、配色、存储和审计表的表头在表格数据滚动时固定于内容区顶部；横向滚动时表头与数据保持列对齐，表格内部不再设置嵌套滚动容器。保存栏固定在卡片底部，不参与内容滚动。

页面结构、统一编辑与生效方式单元格位于 `frontend/src/ui/ConfigurationPage.tsx`；控件宽度档位位于 `frontend/src/ui/configuration-layout.ts`；列宽、对齐、交互状态和容器断点统一维护在 `frontend/src/ui/configuration-page.css`，避免在全局样式中追加局部覆盖。共享 Token 输入与时区组件的基础样式仍保留在全局样式中。

切换分类保留草稿。底部保存栏显示全部未保存项、涉及分类及生效范围；保存与撤销均作用于全部分类。只有改动的字段会提交，重建账号、重启采集器等操作保留影响确认与错误反馈。数字范围和生效方式仍来自服务端配置目录。Portal 登录有效期默认显示为 12 小时，可切换小时、天并输入小数；切换单位不改变时长，接口仍以整数秒保存，范围保持为 1–12 小时。

会话亲和有效期与登录有效期共用“数值＋单位”控件，支持秒、分钟、小时、天。会话亲和默认 1 小时，范围为 30 秒至 30 天，接口继续使用 `30s`、`1h` 等带单位的字符串；切换显示单位不改写配置，编辑回原时长时保留原字符串格式。

Logo、访问凭据、Webhook 和用量清零保留独立操作流程，不包含在底部的统一保存中。配色位于系统设置；用量与额度下的“额度”合并用户额度、官方额度查询与用量维护，清零操作位于配置参数下方，保留影响范围展示、原因填写和二次确认。“模型倍率”和“推理倍率”为独立子配置页，分别展示对应倍率并提供各自的恢复默认操作，跨页草稿仍由底部统一保存。旧的 `section=multipliers` 链接默认进入模型倍率，`section=quota-cache` 与 `section=quota-reset` 进入额度；携带配置键的链接优先定位到该键所属页面。搜索“用量维护”会定位到额度页的清零操作。六类分区由前端组织，所有页面使用原有配置键，不改变配置接口、数据库或已有配置值。

通知设置下仅保留“企业微信通知”子页，集中展示通知开关、发送计划、额度预警和 Webhook 接入。旧的 `section=schedule`、`section=alerts` 链接进入该页，配置键定位仍有效；Webhook 继续独立保存。

已保存的 Webhook 使用独立的 `webhook_display_url` 展示脱敏地址，仅保留 key 的末四位；`webhook_url` 在读取响应中仍为空。兼容未返回展示字段的后端时，显示企业微信固定消息地址并将 key 全部遮蔽，不伪造末四位。点击“更换地址”进入空白编辑框，保存或取消后清理输入；取消保留原地址，清除仍需单独确认并关闭通知。编辑、保存、清除或发送期间禁用冲突操作。“发送测试消息”只确认通道，“发送账号报告”发送当前账号额度报告。

企业微信额度消息统一采用配置中心产品简称，头部显示完整统计时间（含秒和系统时区）、预警阈值与公开站点的 `/usage/` 地址。报告按账号去重，每个账号仅选取常规周额度；附加限额不生成报告行或提醒，缺少常规额度时标为数据不可用。概览包含账号总数、近一小时活跃账号数及正常、预警、耗尽、数据不可用数量；账号级用户数不相加为全局人数。明细优先列出耗尽、预警和数据不可用账号，字段为账号、周额度已用、近一小时用户、剩余重置次数、额度重置时间。消息不包含套餐分布或底部详情入口。

单账号预警、耗尽、恢复和周期重置使用简短事件信息；多账号事件合并成表格，定时报告与事件重合时合并发送。周期重置需要观测到原重置时间已到且新重置时间推进至未来，单纯用量下降不视为周期重置。通知窗口记录增加可选的 `reset_at`，旧记录在下次有效采集时建立基线。仍遵守每条消息 4096 字节上限，超限报错，不静默省略账号。

新 API Key 的默认前缀为 `ccpa_`，生成格式为 `ccpa_<用户标识>_<UUID>`。配置项 `identity.key_prefix` 只作用于之后新建或轮换的 Key；已有 Key 和数据库中显式保存的前缀（包括旧值 `cpa_`）不会因默认值变更而自动改写。

客户端导出的默认 Key 环境变量名为 `CCPA_API_KEY`，由 `portal.api_key_env` 配置。已保存的环境变量名（包括旧值 `CPA_API_KEY` 和自定义值）继续优先使用。

## 配置接口

| 接口 | 用途 | 安全行为 |
|---|---|---|
| `GET /admin/api/onboarding` | 汇总首次配置的真实完成状态 | 只返回状态和数量，不返回 Secret 或账号生命周期状态 |
| `PUT /admin/api/onboarding/preferences` | 保存可跳过配置项的处理状态 | CSRF；只允许已知配置项 |
| `GET /admin/api/settings/configuration` | 按组读取可编辑配置定义、当前值和生效方式 | 管理会话；秘密只返回是否已配置 |
| `POST /admin/api/settings/configuration` | 按键保存通用配置 | CSRF；类型、范围和枚举校验 |
| `GET/PUT /admin/api/settings/general` | 品牌、公开地址、邮箱域、Key 前缀和客户端导出默认值 | PUT 需要 CSRF 与 `confirm=save` |
| `GET /admin/api/settings/workspace` | 存储文件存在性、权限、账号备份摘要和脱敏审计 | 不读取或返回文件秘密内容 |
| `GET/PUT /admin/api/settings/notifications` | 通知调度、阈值与运行状态 | 完整 Webhook 不回显；独立展示调度心跳，失联时隐藏下次发送时间 |
| `POST /admin/api/settings/initial-password` | 设置之后新用户的初始密码 | 只返回配置状态，不回显密码 |
| `POST/DELETE /admin/api/settings/logo` | 上传或恢复品牌 Logo | 文件类型、大小与 SVG 安全校验 |
| `POST /admin/api/settings/management-key` | 轮换管理密钥 | 成功后当前管理会话立即失效 |

完整 API Key、管理密钥、密码和 Webhook 不进入 URL、React Query 缓存、Local Storage 或 Session Storage。一次性凭据只存在于当前 Mutation/Modal 内存，关闭后清理。

`/admin/setup` 只复用配置中心的安全写接口，不再跳转到 CPA、OAuth 或用户创建流程。引导完成状态以 Go Admin 的实时读取为准；浏览器只保存当前会话内的页面选择，不持久化完成状态或秘密。可跳过项目的状态写入控制面设置，因此换浏览器后仍保持一致。

## 存储边界

| 存储 | 内容 | 规则 |
|---|---|---|
| `state/control-plane.sqlite3` | 配置值、账号/路由/Key 元数据、加密秘密和审计状态 | 唯一控制面事实来源 |
| `state/usage.sqlite3` | 用量、用户会话、额度策略和调整 | 与控制面库分离，避免高频事件争用 |
| `secrets/control-plane.key` | 控制面秘密主密钥 | 必须为普通文件、权限 `0600`、与数据库成对备份 |
| `configs/`、`state/gateway/` | 上游配置和 Go Gateway 运行快照 | 由 Go 服务生成，不是人工配置入口 |

Go Admin 只打开既有目标。正式部署必须先存在两份 SQLite 和匹配主密钥；发布脚本不会导入退役控制文件或创建新的生产数据。

## 生效模型

| 模式 | 行为 |
|---|---|
| `live` | 后续读取立即使用新值，不重建数据面 |
| `accounts` | 由账号生命周期流程校验并应用到相关上游账号 |
| `quota` | 下一次 Collector 快照后由 Gateway 执行 |
| `deployment` | 只由目标发布流程应用，不由普通页面刷新触发 |

账号自动切换只允许 `off` 和 `active`。用户周额度的系统默认、个人策略、追加和清零均保留独立审计语义；页面只在进入对应区域时读取破坏性操作影响范围。

用户额度的加权 Token 按“模型倍率 × 推理强度倍率”计算，只在 Collector 接收新事件时写入，不按当前配置重算历史事件。`gpt-6-astra` 的默认模型倍率为 `4`，当前已知的其他模型以及未匹配模型的默认倍率为 `1`；模型名优先取事件的 `model` 字段，仅当 `model` 为空时回退到 `alias`，匹配时忽略大小写和首尾空格。未来新增模型在没有专属配置前使用“其他 / 未匹配模型”倍率。

## 品牌和公开配置

`GET /site-config.json` 仅返回公开品牌、允许登录的企业邮箱后缀与客户端导出字段，不包含 Key 前缀、管理密钥、Secret digest 或其他私有设置。邮箱后缀需要在未登录的使用中心登录页展示，因此属于显式公开白名单。自定义 Logo 通过 `/branding/logo` 输出；SVG 会拒绝脚本、事件处理器、外部资源、实体、`foreignObject` 和危险 URL。

## 验证

```sh
go test ./internal/admin ./internal/branding ./internal/controlplane ./internal/notifications
npm --prefix frontend test
npm --prefix frontend run test:e2e -- --grep "configuration"
make -f scripts/build.mk verify
```

修改设置契约时必须同时更新 `api/openapi.yaml`、生成的 Go/TypeScript 类型、`internal/admin`、`frontend/src/api`、页面测试和 Go Preview fixture。
